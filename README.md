# Past Lights — 日本歴史繁栄マップ

「もし昔の日本にも電気があったら、その時代の人間活動の光はどこに見えただろう？」

縄文時代から現代まで、年代スライダーを動かすと日本の「栄えていた場所」が夜景の光として移り変わる歴史地図です。光は実際の夜間照明ではなく、当時の人口・交易・交通・産業・政治的重要性などから推定した「人間活動の明るさ」です。各時代の相対評価で上位の地点が光ります。

## データについて
- 地点・スコアはすべて出典つきの調査にもとづきます（地点クリックで概要と出来事、専門的な評価根拠を表示）
- 主な出典: 国勢調査（e-Stat）・CODH/Geoshape 江戸期データセット（CC BY / CC BY-SA）・文化庁 国指定文化財等データベース・各自治体史 ほか
- 海岸線: Natural Earth (Public Domain)
- 表示される光の明るさは評価スコアからの変換値であり、スコアそのものではありません

## Visualization（`docs/VIZ_POLICY_v1.md` 準拠 / Phase 1 実装済み）

正本方針は `prosperity-map/docs/VIZ_POLICY_v1.md`。最終原則は **DBの密度 ≠ 地図上の光の密度**。

### §2 光モデルの分離
score から直接ピクセルを描かず、いったん light オブジェクト
`{intensity, radius, footprint, role, era, agg, spread, color, soft, core}` に変換してから描画する
（`computeLights()` → `drawLight()`）。**intensity（明るさ）と radius（空間的な広がり）は別パラメータ**で、
radius は従来どおり score から、intensity は圧縮カーブから作る。歴史評価（score）は一切書き換えない。

### §3 非線形輝度圧縮
既定カーブは `anchor`＝方針書の例示カーブをアンカーにした**対数空間内挿**
（100→1.00 / 80→0.45 / 60→0.18 / 40→0.06 / 20→0.015、20未満は二乗で0へ）。
`BAND_FLOOR`（バンドごとの明るさ下限）は**廃止**（床を敷くと圧縮が打ち消され「安曇野38がそれなりに明るい」問題が復活するため）。

URLパラメータで切替・比較できる:

| `?curve=` | 内容 |
|---|---|
| `anchor`（既定） | アンカー表の対数内挿 |
| `gamma` / `power` | `(s/100)^g`（`&g=3.6` 既定） |
| `exp` | 指数（`&k=5.2` 既定） |
| `drc` | anchorのあとフレーム最大で正規化して再展開 |
| `percentile` | フレーム内順位→anchor |
| `log` / `linear` | 比較用（圧縮しない＝改修前の問題を再現） |

**露出（exposure）**: 圧縮カーブは「地点間の比」を作るためのもので、画面全体の明るさは別に決める
（カメラの露出補正に相当）。単純な倍率だと上位が飽和するのでソフトニー `i' = 1-(1-i)^E` を使う。
E は era ごとの段ではなく**年に対して連続**（`EXPO_KNOTS`）＝再生中に時代境界で明るさが跳ねないため。
BC3000で E≈2.85、1600で E≈2.53、1980で E≈1.35、2026で E=1.10。

### §4 / §5 時代別 Renderer
| era | 年 | 描き方 |
|---|---|---|
| ancient | 〜1185 | 点のみ |
| medieval | 1185〜1573 | 点のみ |
| early_modern | 1573〜1868 | 点 + 交通網（うっすら常時） |
| modern | 1868〜1945 | 点 + 線 + 主要都市の面化 |
| contemporary | 1945〜 | 面主体（都市圏 + 弱い地方光） |

footprint は5種: `point` / `blob`（大都市＝2-4個の楕円ブロブの重ね）/ `coastal`（港＝最寄り海岸の接線方向に扁平）/
`sharp`（鉱山＝小さく鋭い）/ `haze`（一般市区町村＝コアを持たない微光）。
交通網は`ERA_NET`で近世以降うっすら常時表示（「交通エッジ」トグルで通常の濃さ）。

### §6 / §9 現代の階層化
- **都市圏の凝集度（agglomeration）**: 近傍32kmの光の強度をガウス重みで合計し、その平方根で面の広がりを決める。
  東京圏のように隣接自治体が多数光る場所ほど面が大きく、札幌・仙台のような単独の地方中枢は小さい。
  **スコアを一切触らずに「三大都市圏 ≫ 札幌福岡仙台 ≫ その他」の階層を作る**のがこの仕掛け。
- **T2N（機械生成の全市区町村）でスコア58未満は `role='minor'`** → コアを持たない平たい微光として
  地方の下地に溶かす（＝score38級を独立した明るい丸にしない）。
- 現代（1950年以降）の点灯上限は 520（それ以前は200）。「その他微光」を面として敷くため。
- 面で描く時代はコアの下限アルファをほぼ0にする（市区町村の数だけ白い粒が並ぶ格子模様を防ぐ）。

### §10 再生体験
- 既定44秒（`?dur=` で20〜120秒）。**非線形時間**（`PLAY_KNOTS`）でBC3000〜1200に約24%、以降に76%を配分。
- 時代が変わると画面中央に**時代名を大きくフェード表示**（2.1秒）。
- 再生中は凡例・免責・サブタイトル・各トグルボタンを**フェードアウトしてHUDを最小化**。
- スライダーを掴むと再生は停止する。

### §12 HUD削減
- 全国画面の常時表示は「**1600年 / 安土桃山時代**」だけ。時代名は年から導出
  （縄文/弥生/古墳/飛鳥/奈良/平安/鎌倉/室町/戦国/安土桃山/江戸/明治/大正/昭和/平成/令和）。
- 補間/実測・点灯地点数・Renderer・role内訳・カーブ名・露出値は**「この光について」モーダル内の技術情報**へ移した。
- §14 免責は右下に小さく維持。

### §13 彩度
色（種類）・グラデーション比率は改修前のまま。彩度は上げていない。

### デバッグ用フック
`?year=1600` で起動年指定。`window.PL.setYear(y)` / `.lights()` / `.play(true)` をコンソールから叩ける。

### レスポンシブ対応（`docs/VIZ_POLICY_v1.md` 追補2026-09-04 準拠）
優先順位は **Timeline > Main Japan Map > Controls > Insets**。`#timebar`（年代スライダー）の
高さ・タップ幅は画面幅に関わらず固定し、狭くなるほど操作性を犠牲にしないようにしている。

画面幅（`#stage` の実測 clientWidth、`resize()` で毎回再判定）で3段階に分岐（`BP` 変数）:

| 幅 | 南西諸島 | 小笠原 |
|---|---|---|
| wide（≥1000px） | 現状どおり枠付きインセット | 枠付きインセット |
| mid（600-999px） | 縮小した枠付きインセット | **非表示**（作らない） |
| narrow（<600px） | **圧縮projectionで本図内に直接描画**（枠なし） | **非表示**（作らない） |

**圧縮projectionの実装** (`projCompressedSW()`): 元の緯度経度データは一切変更しない。南西諸島
インセット範囲（`INSET_SW`）のクラスタ中心からの相対距離を `SW_COMPRESS`（既定0.34）倍に縮め、
九州南西沖の固定アンカー点（`SW_ANCHOR_GEO` = 薩摩半島沖）を中心に、**本図と同じ拡大率
(`view.sc`)** で再投影する。つまり別スケールの縮小地図を貼り付けているのではなく、「実際の距離を
詰めて」本図の一部として配置している。アンカーは左下（凡例/HUD帯）・上端（タイトル）・右端と
重ならないよう `W`/`H` に応じてクランプする。

**座標変換の一貫性**: `computeLights()`（点灯位置）・`drawEdges()`（交通網）・`hit()`（クリック/
ホバー判定）・`drawLand()`（海岸線）は全て `projFor()` を経由して座標を得るため、`projFor()` 内で
圧縮モードに分岐させるだけで描画とヒット判定が自動的に一致する（display transform層の差し替えの
みで実装。個別の当たり判定ロジックは持たない）。小笠原がmid/narrowで非表示になる場合も同様に
`projFor()` が `[null,null,null]` を返し、`computeLights()`/`drawEdges()`/`hit()` がその地点を
スキップする形で統一している。

リサイズは `window` の `resize` イベントで `resize()` が再実行され、`BP` の再判定・インセットの
再構築・投影の再計算まで動的に追従する（リロード不要）。

**既知の制限**:
- mid/narrow幅では**小笠原諸島（父島・母島）を描画しない**。地図上での選択も不可（地名検索UIが
  無いため、現状これらの地点を狭幅・中幅画面で開く手段はない）。wide幅（≥1000px）に戻すか、
  ウィンドウを広げれば従来どおり選択できる。
- narrow幅の圧縮projectionはクラスタの相対位置関係を保つ簡易表現であり、九州本土との実際の距離
  比は保持しない（意図的な「距離圧縮」であり、モーダルの免責文にもその旨を明記）。

## Phase 2 残項目

### §7 ズーム / LOD（未着手）
現状は全国固定ビューのみで、パン・ズームが無い。方針書 §7 の「全国表示=主要な光／ズームで地方都市・宿場・鉱山を追加／
さらにズームで詳細」を実装するには:
- ビュー変換（`view.sc/ox/oy`）へのパン・ズーム操作と、ズーム率に応じた表示地点数の段階制御（現在は `topNFor(y)` が年だけで決まる固定値）
- ズーム率に応じた radius / core / 面ブロブのスケール規則（今は画面固定pxなので、ズームすると光が相対的に小さくなる）
- インセット（南西諸島・小笠原）とズームの整合
- ラベル表示のLOD（現在は上位26件固定）

### urban footprint の本格化（§4 / §6 の残り）
現在の面表現は「決定的な擬似乱数で置いた2-4個の楕円ブロブ」という簡易表現で、実際の市街地形状ではない。
- 市区町村の行政界ポリゴン、または人口集中地区（DID）ポリゴンを取り込んで実際の footprint で描く
- 大都市圏を「地点の集合」ではなく1つの連続した面として扱う集約（東京都区部＋周辺自治体を1つの光源に統合）
- 港の扁平方向は最寄り海岸線の接線で近似しているが、湾の形状までは反映していない

### その他
- **`places.csv` の `k`（種類）判定**: `京都市` `大阪市` `東京都区部` `堺市` などが `kt` に `port` を含むため
  `k='port'`（青）に倒れており、都市圏が青系で描かれる。色の意味（§13）としては `capital`/`urban` を優先すべき。
  Viz側では `role` を `k` と独立に判定して形だけは正しくしてあるが、**色はデータ側の修正待ち**（`tools/build_ui_data.py`）。
- 2026年に `東京都区部`(T1) と `特別区部`(T2N) が同一地点で二重に点灯している（実害は小さいが要整理）
- 地名検索UIが無い（消灯地点は座標クリックでしか開けない）
